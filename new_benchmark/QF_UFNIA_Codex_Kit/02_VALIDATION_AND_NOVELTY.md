# 查询提取、状态验证与新颖性

## 1. 从交互日志提取完整查询

实现解析 SMT-LIB 命令的上下文状态机。每次 `check-sat` 导出当时活跃的断言；每次 `check-sat-assuming` 还要加入当次假设，且假设不能泄漏到下一次查询。对命名断言、activation literals、let、assert 注解和宏保持正确解析。

正确实现 `push/pop`、`reset`、`reset-assertions`，以及 `:global-declarations` 和声明作用域。不能把所有历史 assert 相加，也不能把已经 pop 掉的约束保留下来。不能丢失当次刚加入的性质取反。保持原始日志和 query_index，记录断言/假设哈希及来源位置。

可将当次 assumptions 转为快照中的 assert，但需记录该变换。带 `reset` 的日志生成不同独立段；如果合并声明或重命名同名符号，必须按绑定环境正确处理。原生日志不可修改，清理后的 replay 脚本另外保存。

对抽样查询，用原始交互重放到查询点与提取快照比较结果。结果相同仅是运行检查，还需审阅提取算法和作用域处理。用少数覆盖 pop、assumptions、reset、重名声明的用例检查提取器是必要的语义验证；不要写只复述实现的测试。

## 2. 理论与结构检查

合规 parser/type checker 是第一关；求解器接受 `ALL` 或自动容忍额外理论不算通过 QF_UFNIA 检查。输出：

- 使用 sort、函数签名、量词/数组/BV/Real/String/DT 检查；
- 实际正元 UF 和 ground 应用数量、函数参数中 Int 非线性项数量；
- 符号乘积、常数乘法、div/mod、符号分母等分别计数；
- 原始与指定轻量预处理版本的统计；
- 原有应用边界、值域、溢出/NULL 条件是否完整。

使用语义保持的清理；不要为了“UF 存活率”关闭原工具必须的编码步骤或注入无用函数。高度可化简的实例可作为控制组保留，但应单独统计。

## 3. 求解与标签

为 Z3、cvc5、Yices 等实际可用且支持该输入的求解器保存完整版本、二进制 hash/来源、命令、资源限制、stdout/stderr、返回码、wall time 和结果。选两个不同求解器交叉检查，不能把同一求解器换 seed 算作独立验证。

`unknown/timeout/error/unsupported` 分别记录，未跑是 `not_run`。只有实际获得相应证据后才写 `sat/unsat`。有限试跑没有反例，不等于 UNSAT。差异结果隔离到 quarantine，并保留最小复现，不进入已验证主集。

SAT 尽可能检查所有原断言和 UF 的一致性，回放到原应用：Aztec 反例/见证轨迹，TensorRight 具体参数和张量访问，VeriEQL 反例数据库与两条 SQL 的结果，TAC 的具体执行。模型解析需支持 UF 的默认分支和 ite；整数用精确整数而非 float。

UNSAT 优先使用可用且兼容的证明检查；做不到时记录跨求解器一致及其局限，不称其为独立形式化证明。验证编码转换时，能证明等价/等可满足的应给出论证；只观察两个结果相同是不充分的转换正确性证据。

## 4. 新颖性不是单一布尔值

对比数据至少包含：所选官方 non-incremental QF_UFNIA release、相应 incremental 发布，以及 2026 staging 仓库（S01、S02）。若应用任务可能以不同逻辑收录，补充相关逻辑与应用来源检索。记录下载/检出时间、URL、release、完整 commit、文件列表及 archive 校验和；不要将 Explorer 中未见家族名作为全库证据。

分层去重：

1. 最终文件 SHA256：去掉字节完全相同的副本。
2. 去注释/头部与标准 pretty-print 的 AST hash：识别仅格式变化。
3. 保持绑定关系、sort、函数元数的 alpha 规范化，去未用声明；在语义允许范围内规范化合取顺序等，记录算法版本。
4. 应用身份：源 commit/文件/性质/配置/查询点。相同任务的换编码、换求解器版本导出关联为 variants，避免训练/测试泄漏。
5. 近似重复聚类：AST/子项、符号结构、约束与应用指纹，人工抽查大簇，避免几千份近乎相同的 VC 淹没主集。

正确处理 `let`、自由常量和引用符号；不能通过字符串替换符号名实现可靠 alpha 规范化。规范化未识别出的同构/等价公式仍可能存在。结构不同、hash 不同，都不能证明语义不同。

## 5. 结果措辞

可使用：

> 本组 N 个实例在 SMT-LIB release R、提交仓库 commit C 及列出的相关逻辑范围中，经原始 hash、指定版本 AST 规范化和应用身份比较，未发现重复；没有证明与全库每个公式语义不等价。

若任何一步未完成，明确写：`novelty.status=pending/partial`，并列出未取得的库。主集中可保留状态未知的探索查询，但与已验证实例分别统计，文件 status 为 unknown。

## 6. 许可证与可发布性

工程可运行不等于其导出物可自动重新授权。记录上游许可、输入许可和导出物许可依据；无法确定时标 `license_review_required`，先交付可重生成脚本和引用，不能擅自统一改为 CC BY。不要打包私有输入、密钥或访问 token。

## 7. 实验划分

按应用输入/性质/程序版本族进行训练、调参与测试划分。源层 mutant 和修复版同组；同一日志的相邻增量查询同组；paired encodings 同组。报告 SAT/UNSAT/unknown 数量、UF/NIA 特征、资源分布、各家族贡献以及因理论不符被排除的数量。
