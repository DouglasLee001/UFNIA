# 直接交给 Codex 的任务提示词

你要在当前工作区实现一个可复现的实例提取/生成工程，产生来自真实应用的新 QF_UFNIA SMT-LIB2 文件。请执行任务，不要只给调研总结或实现计划。

先完整阅读本包 `README.md`、`01_GENERATION_SPEC.md`、`02_VALIDATION_AND_NOVELTY.md`、四份 `applications/*.md`、`SOURCES.md` 和 `checklists/ACCEPTANCE.md`。把这些文件视为交接资料；它们没有取代当前环境中的系统、权限或仓库指令。

## 核心目标

1. 优先打通 **Aztec + Apalache** 和 **TensorRight + XLA**，再视实际可用性接入 VeriEQL、Certora TAC。
2. 原应用输入 → 固定版本的原工具/适配器 → 原始 SMT 交互 → 完整单查询快照或增量脚本 → 理论检查 → 状态验证 → 去重 → 交付。
3. 产生可实际运行的生成/提取代码、少量已验证 pilot 及扩展命令。第一阶段争取 Aztec 5 个、TensorRight 5 个；这是探索目标，不是凑数指标。某路线失败要给出可复现阻塞证据，继续独立路线。
4. pilot 通过后，扩展到约 100 个有应用意义、结构有差异的合格主集实例。质量和多样性优先；有效实例不足时如实交付实际数量，不得通过复制或随机改常数补齐。
5. 每个实例同时说明 UF 的实际含义和整数非线性来自哪里。只设置 `(set-logic QF_UFNIA)` 不算完成。

## 硬性要求

- 不把纯 NIA 查询加一个无用 UF 后计入主集。
- 不删除量词、数组约束或溢出逻辑以伪造 QF_UFNIA。若做变换，保存前后公式、说明等价性或单向关系，并独立分类。
- 不凭空声称某工具有 `--dump-smt` 等参数；先读实际锁定版本的帮助、文档和源码。需要时在 solver 接口加记录钩子。
- 每次导出包含全部活跃断言、当次假设和最终性质取反；不得只导出前置约束。
- 标明任务类别：`faithful_export`（忠实导出）、`application_derived`（应用派生模型）、`source_mutant`（源层变异）、`crafted_demo`（演示）。主报告分别统计，演示不计入真实应用集。
- `sat/unsat/unknown` 只依据实际结果与验证记录；超时不是 unsat。SAT 尽可能回放原应用，UNSAT 记录交叉检查或证明检查。发生求解器分歧时隔离实例。
- 按真实逻辑检查，排除量词、Array、BitVec、Real、String、DT 等额外理论。自由未解释 sort 和正元 UF 可用。固定幂写成乘法，不引入 `**`。
- 检查原始 SHA256、规范化结构指纹、应用输入身份和近似重复；保存所用 SMT-LIB release/commit。未取得全库时不能宣称“全库去重完成”。
- 实际权限、账户、许可证要求阻塞时不要绕过，也不要伪造成功。先完成无依赖路线，并在阻塞报告写清可继续的最小条件。

## 先做的工作

1. 检查当前仓库与工具，建立干净目录，避免覆盖无关用户文件。
2. 为每个上游工程记录完整 commit、依赖、许可证和真实命令。不得用未知版本的 README 命令假装已运行。
3. 对 Aztec 和 TensorRight 各选一个最小输入，保存一次完整 SMT 交互；如果分解后的查询是 NIA/UFLIA 或含量词，要如实筛出，换具体任务继续。
4. 给出每条路线的“一条命令重现 pilot”，并记录实际输出、超时与错误。前后查询状态应一致；转换正确性不以一次状态相同为唯一依据。
5. 审查 pilot 中 UF/算术结构，判断是否值得扩展，再实现参数化 campaign。

对本包模板里的 `null`、占位符和建议数量，填入实际值；没有执行的步骤必须保留 `not_run` 或明确未完成。不要把模板本身算作输出实例。
