# 默认执行顺序与停止条件

## 阶段 A：建立实际环境记录

检查当前工作区指令，选择独立输出目录。核查应用仓库许可证后按固定完整 commit 获取，不向远端提交变更。记录系统、Java/Node/Haskell/Python、SMT solver 及依赖版本。允许按实际环境选择容器或本地安装，但不得把本包里的建议命令当作已验证命令。

建立 `upstream-locks/`，每个应用保存 `repository_url, commit, input_paths, toolchain, license, retrieval_date`。本包没有锁定现成下载版本；后续必须实际填写。

## 阶段 B：两个优先来源各打通一个查询

Aztec 从仓库的局部不变量检查入口开始。TensorRight 从符号 stride 的整数、无 reduction 重写开始。每条路线先收集一个 raw log，确认性质取反和 assumptions 完整，再提取单查询。

若第一个任务被筛为 UFLIA/NIA 或含量词，这不是导出成功的主集实例；保留理由，换任务。不要绕过筛选。

## 阶段 C：pilot

建议尝试 Aztec 5 个、TensorRight 5 个；若另外两条路线工具可用，各尝试 3 个。数字仅用于控制探索规模。每个任务先给每个 solver 60 秒；困难查询可另开明确标注的 300 秒扩展批次。记录线程数、内存上限、随机种子和超时机制。

pilot 必须先通过完整查询提取、语法/理论、provenance 和状态审阅。不要立即批量展开数千任务。

## 阶段 D：应用有意义的扩展

| 应用 | 首选扩展轴 | 不应作为新任务的做法 |
|---|---|---|
| Aztec | 实际转移/性质组合、合法符号配置、可达状态/见证任务、明确边界内的实例规模 | 仅换变量名、固定所有非线性配置后仍声称保留原难点 |
| TensorRight | 新源规则、非 reduction 合法组合、rank 实例、源层前提弱化、符号 stride/填充关系 | 仅把所有尺寸常量化，或把带量词的 Conv 子任务强贴 QF 标签 |
| VeriEQL | 整数查询对、行数界、join 结构、真实完整性约束、可解释源层错误 | 将真实金额浮点悄悄替成整数，或忽略 NULL/bag 语义 |
| Certora/TAC | 新输入/性质/版本、实际路径子任务、原有正确与缺陷版本 | 只对旧 SMT2 随机扰动常数、任意删除溢出或数组约束 |

扩大到约 100 个主集实例前，审阅每个家族结构簇。应用派生与 mutant 的规模单独报告。SAT/UNSAT 不要求硬凑比例；可以增加实际可达性/见证和已知缺陷任务，但不能反转 status 或任意修改终式得到预期答案。

## 阶段 E：去重、重跑与交付

固定官方库快照及 staging commit，运行分层去重。对最终文件重算 hash 和 metadata。提供一条命令重现 pilot、一条命令重跑 solver 检查，以及从下载到生成的完整参数说明。最后按 `checklists/ACCEPTANCE.md` 填写真实结果。

## 阻塞与停止

- 一条路线需要不可用凭据/授权时，写最小阻塞说明，继续其他独立路线，不擅自开通服务。
- 导出器未能记录完整查询，不能以半成品 SMT2 宣称完成。
- 理论不符无法保持语义地转换时，发布为排除/另逻辑资料，不强行转为主集。
- 发生 solver 分歧或 SAT 无法回放时隔离，不提前定性工具有 bug。
- 若环境允许的工作范围内只能完成 pilot，交付代码、pilot、失败日志和扩展入口；不要捏造完整 campaign 已执行。
