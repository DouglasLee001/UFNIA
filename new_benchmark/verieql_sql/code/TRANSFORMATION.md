# Equality-only label-domain abstraction

The official v1.0 encoder declares SQL column tags as *symbolic* constants of the interpreted String sort, and NULL takes a row and such a tag. No distinctness assumption is invented: two tags can alias in the original model. Splitting NULL into independent per-column predicates would in general lose that relation and is not used here.

For a finite quantifier-free ground formula, the transformer accepts String-valued constants and uninterpreted-function signatures, with equality, distinct and ite as the only interpreted operations whose signatures mention String. It rejects every String literal, length/concatenation/ordering/regular-expression/sequence operation, and every quantifier. It replaces the entire String domain with one fresh free sort and rebuilds all constants, function signatures and terms in a single consistent map. Every equality, possible alias, NULL constraint and non-String term is retained.

Equisatisfiability: from a satisfying original model, use the finite equivalence classes of observed ground String terms as the observed elements of the free domain, and preserve all observed UF results. Conversely, a satisfying transformed finite ground model mentions only finitely many label values. Inject those values into distinct concrete strings; preserve observed UF results on the finitely many argument tuples and extend all remaining total-function entries arbitrarily. Equality, distinctness, ite and UF congruence are preserved in both directions, so induction over the ground AST preserves every assertion. The infinite supply of strings supplies all finitely many required values. There is no quantifier or interpreted string operation that observes unmentioned domain elements.

This establishes equisatisfiability under the explicit AST guard; it does not claim textual identity, nor preservation for formulas containing real string operations. The original formula, transformed formula, counts, paired solver outcomes and concrete SQL replay are checked separately inside the temporary run directory. Only the final strictly audited SMT2 is retained; intermediate artifacts are removed when the TemporaryDirectory closes. The application SQL inputs are also classified independently: kit-proposed Orders pairs are application_derived, not public production workloads or paper benchmark exports.
