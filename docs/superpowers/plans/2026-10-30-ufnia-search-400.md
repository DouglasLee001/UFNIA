# UFNIA 局部搜索与 node3 实验实施计划

> For agentic workers: use subagent-driven-development; execute continuously with targeted tests and independent review.

**Goal:** 改进真正的 UFNIA 局部搜索，在 `/data/shared/lbh/QF_UFNIA/sat/QF_UFNIA` 的 572 个实例中，按用户最新澄清 **仅在 node3 开180并行**、每例600秒，得到至少400个原公式模型验证通过的SAT。此前 node4 实验已停止，仅保留历史记录，后续不得再启动。

**Architecture:** 将 UF 应用以受控观察标记送入同一 Z3 前端处理链，让消元和规范重命名同步作用于公式与观察表达式。GMP 核心接收观察表达式，按当前具体实参值维护同余桶，生成结果统一、实参分离与算术补偿邻域，并以 UF 与算术的联合评分选择操作。保留最终精确同余与原断言模型验证。

**Tech Stack:** Python 3.12、Z3 4.16前端、C++17/GMP成熟搜索及UF扩展、SSH node3、180个独立任务。最终mature核心不链接Z3；原core后端单独保留系统Z3 AST库兼容路径。

## 验收要求

- 至少 400 个不同 benchmark，必须同时满足 `sat`、`validated=true`、`original_model_validated=true`；仅核心 SAT、编码模型或读入通过均不计入。
- 真实实验运行在 node3，工作池 180 并行，记录实际 hostname、并发峰值、资源、源码和二进制哈希、种子、benchmark 哈希。
- 每例端到端墙钟最多 600 秒，包含前端、读入、搜索、精炼与验证；超时杀死整个进程组。
- 真正实现 UF 邻域和可比较的交互策略及评分；不以调用完整 SMT 求解或复用既有解来替代本算法。
- 完整遍历目标集合，保留逐例结果、模型、日志、family 汇总和可重复运行命令。
- 未达到 400 时继续分析失败类别、改进算法并进行新版本实验，不把目标缩小为读入或小样例成功。
